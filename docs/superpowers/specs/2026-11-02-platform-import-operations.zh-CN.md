# 比赛数据导入训练平台：操作说明

本说明适用于加入GZCTF/CTFd适配的新版训练平台。旧版线上页面不会自动获得这些功能，需要先部署匹配的新版镜像和数据库迁移。本轮仅完成本地代码及验收，尚未发布更新包。

## 导出源数据

### GZCTF

使用比赛管理里的导出功能获得GZCTF-GAME ZIP。此包通常含题目、附件、镜像引用和比赛配置，不含账号、提交和成绩，也不含镜像层；界面预检会明确提示。镜像仍需能从现有Harbor拉取，导入不会主动拉取或启动它们。

### CTFd

使用管理员后台的设置/备份导出完整ZIP，应包含db/*.json和uploads/目录。不要仅导出公开题目列表或网页；它们没有完整账号和历史数据。不要在聊天粘贴密码、Token或原始数据库内容，完整包作为私有文件提供即可。

标准题、动态计分题、静态Flag、提示、多附件、账号、队伍、提交、解题、奖励可识别。正则Flag、非标准容器插件等无法保证等价转换时会阻断并指出对象；未知自定义表会列为未映射，不静默声称迁入。实际站点兼容性要用该站完整包核对。

## 在新版平台导入

1. 用管理员账号打开「管理 → 数据导入」。
2. 选择ZIP，填写固定的来源标识，例如campus-ctfd或campus-gzctf。以后从同一平台迁入时沿用此标识，不同平台必须分开；同名题目或同编号不会因此串数据。
3. 默认新建比赛同名路线草稿，也可选择已有技能；必要时改路线名称。选择是否迁入账号、是否保留历史。
4. 点击「检查导出包」。核对题目、资源、账号和历史数量，处理红色问题。重名账号可在对应问题下填写新用户名后重新检查；邮箱冲突不自动合并，也不会覆盖已有账号；可以明确勾选“不创建来源账号，只保留历史记录”，跳过该账号并继续迁入其余账号。跳过的源账号不会自动绑定现有账号。
5. 确认报告后点击「确认导入」。成功后进入路线草稿、题目库检查，再发布。原停用题保持停用；导入本身不会让题目对学员开放。
6. 同一个来源、同一个文件和相同选项再次执行会返回原批次，不重复导入。变更包复用已有题目并保留本地人工修改，不作为强制覆盖同步工具。

如源包中有远程附件，仅保存链接并提示外部依赖，服务器不会替你访问或下载该URL。正文资源会重写为本地权限检查后的资源地址。多附件题下载ZIP；动态附件的个人分配文件和补充附件分别下载，不会暴露别人的附件池。

## 账号登录和历史

- 受支持的CTFd旧密码可直接用于首次登录，验证成功后自动升级；之后密码修改或重置只使用新平台的密码格式。
- 验证邮箱状态、封禁状态保持。源管理员不会自动成为新平台管理员。没有或不支持旧密码摘要的账号必须重置密码，不会被分配统一默认密码。
- 管理员在「历史数据档案」查看迁入的账号/队伍、提交及奖励；用户在个人菜单「比赛历史」查看自己的历史。队伍解题按队伍归属显示，不算作每个人的独立通关。
- 历史记录不增加训练排行榜分数或训练完成记录。未导出的历史分数显示“未提供”，不以当前题目分值补算。
- 未选择迁入账号时，历史仍可作为管理员档案保存；没有本地账号映射的源用户暂时不能在个人页查看。

## 更新与恢复

部署前备份数据库、配置、持久化文件和DataProtection密钥，保持它们相配。新迁移创建来源映射、批次、历史成员/提交/奖励表；不要先清库或对源CTFd执行还原。若整体恢复旧版本，使用相配的升级前数据库/文件备份和旧镜像，不把新结构数据库直接交给旧版本。

本次真实GZCTF样本已经验收。CTFd真实完整备份尚待提供，后续只需上传预检即可定位该站尚需适配的插件或自定义字段。
