# 比赛数据导入训练平台：操作说明

本说明适用于加入GZCTF/CTFd适配及可选旧成绩接续的新版训练平台。旧版线上页面不会自动获得这些功能，需要先部署匹配的新版镜像和数据库迁移。离线更新命令与验收边界见[课程编排版离线更新说明](../../../deploy/offline/COURSE_AUTHORING_UPDATE.zh-CN.md)；更新平台不会自动导入源站数据。

## 导出源数据

### GZCTF

使用比赛管理里的导出功能获得GZCTF-GAME ZIP。此包通常含题目、附件、镜像引用和比赛配置，不含账号、提交和成绩，也不含镜像层；界面预检会明确提示。镜像仍需能从现有Harbor拉取，导入不会主动拉取或启动它们。

### CTFd

使用管理员后台的设置/备份导出完整ZIP，应包含db/*.json和uploads/目录。不要仅导出公开题目列表或网页；它们没有完整账号和历史数据。不要在聊天粘贴密码、Token或原始数据库内容，完整包作为私有文件提供即可。

标准题、动态计分题、静态Flag、提示、多附件、账号、队伍、提交、解题、奖励可识别。CTFd-Whale 的 dynamic_docker 题已适配：迁入镜像引用、HTTP/direct 端口、CPU 和内存。固定 Flag 题保留静态校验；无固定 Flag 的 Whale 题使用每实例随机 Flag，并兼容容器的 FLAG 环境变量。原 Docker/FRP 控制配置和活动容器不迁入，沿用目标训练平台独立配置。ZIP 不包含 Docker 镜像层，部署前需确认目标机器能拉取镜像。

普通题没有 Flag 时迁入为停用草稿，补配后才能发布。正则 Flag 和未支持的其他插件仍阻断并指出对象；未知自定义表会列为未映射，不静默声称迁入。零字节空表受支持，非空损坏 JSON 仍会阻断。

## 在新版平台导入

1. 用管理员账号打开「管理 → 数据导入」。
2. 选择ZIP，填写固定的来源标识，例如campus-ctfd或campus-gzctf。以后从同一平台迁入时沿用此标识，不同平台必须分开；同名题目或同编号不会因此串数据。
3. 默认新建比赛同名路线草稿，也可选择已有技能；必要时改路线名称。选择是否迁入账号、是否保留历史。若要把 CTFd 旧总分作为新排行榜起点，显式勾选“合并 CTFd 旧成绩到训练排行榜”；默认不勾选，开启后必须同时保留账号与历史。
4. 点击「检查导出包」。核对题目、资源、账号和历史数量，处理红色问题。重名账号可在对应问题下填写新用户名后重新检查；邮箱冲突不自动合并，也不会覆盖已有账号；可以明确勾选“不创建来源账号，只保留历史记录”，跳过该账号并继续迁入其余账号。跳过的源账号不会自动绑定现有账号。
5. 确认报告后点击「确认导入」。成功后进入路线草稿、题目库检查，再发布。原停用题保持停用；导入本身不会让题目对学员开放。
6. 同一个来源、同一个文件和相同选项再次执行会返回原批次，不重复导入。变更包复用已有题目并保留本地人工修改，不作为强制覆盖同步工具。

如源包中有远程附件，仅保存链接并提示外部依赖，服务器不会替你访问或下载该URL。正文资源会重写为本地权限检查后的资源地址。多附件题下载ZIP；动态附件的个人分配文件和补充附件分别下载，不会暴露别人的附件池。

## 账号登录和历史

- 受支持的CTFd旧密码可直接用于首次登录，验证成功后自动升级；之后密码修改或重置只使用新平台的密码格式。
- 验证邮箱状态、封禁状态保持。源管理员不会自动成为新平台管理员。没有或不支持旧密码摘要的账号必须重置密码，不会被分配统一默认密码。
- 管理员在「历史数据档案」查看迁入的账号/队伍、提交及奖励；用户在个人菜单「比赛历史」查看自己的历史。队伍解题按队伍归属显示，不算作每个人的独立通关。
- 未选择合并旧成绩时，历史记录不增加训练排行榜分数或训练完成记录。选择合并后，个人旧总分和通关单独建立固定基线。历史中未导出的逐次分数仍显示“未提供”，不能拿当前题目分值补填当年的每次得分。
- 未选择迁入账号时，历史仍可作为管理员档案保存；没有本地账号映射的源用户暂时不能在个人页查看。

## 更新与恢复

部署前备份数据库、配置、持久化文件和DataProtection密钥，保持它们相配。新迁移创建来源映射、批次、历史成员/提交/奖励表；不要先清库或对源CTFd执行还原。若整体恢复旧版本，使用相配的升级前数据库/文件备份和旧镜像，不把新结构数据库直接交给旧版本。

## 大备份上传与反向代理

应用上传压缩包上限为 **256 MiB**，解压后文件总量上限也为 **256 MiB**，最多 10000 个 ZIP 条目。超过限制需要分批导出或评估流式导入方案，不要关闭边界检查。此上限只用于新平台导入接口，不影响原 CTFd。

入口 Nginx/宝塔若仍为默认小上传限制，可能在到达应用前返回 413。请在训练平台现有网站的对应 `server` 配置内设置（不是题目 TCP 转发的 `stream` 块）：

```nginx
client_max_body_size 257m;
```

在现有反代应用的 `location` 中保留原有 `proxy_pass`、WebSocket 和转发头设置，补充：

```nginx
proxy_read_timeout 900s;
proxy_send_timeout 900s;
```

测试 Nginx 配置通过后平滑重载，无需停止 CTFd、数据库、frps 或 frpc。备份含大量账号/提交时执行会比预检慢，避免重复点击；若连接中断，使用相同文件、来源和选项重新预检后重试，已提交批次可安全复用。

## 实际样本说明

已按真实 GZCTF 样本及本次 CTFd 完整备份适配。CTFd 样本包含 273 道题、1320 个账号、29587 条提交、13132 条解题引用、215 条奖励；解题引用与提交按来源编号合并，不能将二者数量相加。84 道 Whale 题中 76 道为动态 Flag、8 道为固定 Flag。

此样本的 3 个超长用户名及 1 个空白用户名需要在预检中明确改名或跳过；不会替管理员静默改名、合并或覆盖现有账号。全部账号密码格式受支持，但不会猜解或显示用户原密码。历史分数没有导出的字段仍显示未提供，动态计分规则和来源信息保留为档案。


## 合并 CTFd 成绩：旧总分作为起点

此选项仅支持个人计分的 CTFd 完整备份，不把队伍成绩分配给队员。初始总分按导出包中各题当前分值与个人唯一正确解题、奖励/扣分恢复；动态题使用导出时的分值固定建账，不继续按新平台解题人数降分。隐藏和封禁账号不公开上榜。

旧通关同步，保留最早成功时间；这些题已计入旧总分，之后重复答题不会再加分。旧题暂时停用、未发布、缺镜像或后来改分，均不改变初始基线。新完成的原生题目按训练规则继续累计。排行榜只显示合并后的累计总分，不显示旧成绩与新增积分的拆分；趋势图按原解题、奖励和扣分时间累计，用导出时分值回算历史趋势；可拖动时间缩放查看 2024 年等历史时段。它不代表当年的每次动态分值，末端与累计总分一致。原始历史缺失或无法核对时回退为迁入日起点。同分的排序仍使用训练平台规则，可能与原站不同。

每个固定来源只迁入一次成绩。同文件、同跳过账号集合重试复用原批次；更换备份或跳过集合不能重新建账/追加旧分，若只迁入后续内容须关闭成绩合并。已有仅迁历史的批次可用原始文件开启成绩迁入，但映射题目若已合并、删除、丢失，或已有冲突的本地通关，预检会阻断，不能静默覆盖现有成绩。封榜备份也会阻断，避免把公开封榜值与完整历史混淆。

迁移前备份数据库、文件和配置；本功能增加来源级成绩迁入标记、个人基线和通关关联结构。不要清空源 CTFd 或重启其容器。成功后先核对预检报告、排行榜和旧通关，再整理发布题目。原始 ZIP 必须保留，用于来源核对与可重复恢复。

正式启用成绩迁移前，应以最终确认的完整备份为准。该基线对应 ZIP 导出时的数据，不会实时同步仍在运行的 CTFd；源站后续新增账号、答题和积分不会自动追加。
