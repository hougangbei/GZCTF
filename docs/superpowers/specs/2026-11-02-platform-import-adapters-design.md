# GZCTF 与 CTFd 导入适配设计草案

状态：已按用户确认范围完成实现；规格与代码质量审查通过。实测记录见执行文档。参考基线：12221da9。

## 1. 已确认的事实

用户提供 ExSolo个人赛-export-20261102-085902.zip，约43.65MiB，47个条目，展开46,845,566字节。manifest声明GZCTF-GAME/1.0，导出器1.9.0.0。包含26道题（16附件题、10动态容器题）、7个题型分类、19个文件，25题启用、1题停用。文件SHA256与文件名均一致。18题有附件，其中4题为带补充附件的容器题；4道动态容器题没有Flag模板及静态Flag，原代码确认缺省时生成随机 flag{GUID}，适配时保持该行为。包中没有账号、队伍、提交、成绩记录和Docker镜像层。

现有后台/api/admin/imports/zip只识别内部CanonicalChallengeImportBatch格式，不能直接解析GZCTF-GAME。现有比赛域另有旧比赛导入代码，但不是训练平台四层体系的导入；不能直接复用数据库还原或让用户先导入旧比赛再做启动迁移。旧迁移器仍以LearningPath为主要目标，附件与容器互斥、只接受单一静态Flag、没有账号与成绩迁移，必须新增格式适配与当前模型写入层。

CTFd校园地址https://ctf.campus.nynusec.com/在本次工具访问中连接失败，无法确认实际版本和插件；不能根据域名断言已验收。官方完整导出为db/*.json（results数组）和uploads/*，有users、teams、challenges、flags、hints、submissions、solves、files、config等表。真实包是插件兼容验收依据，普通网页或公开API不能提供全部账号资料。

## 2. 推荐范围与替代方案

推荐统一后台导入向导：上传ZIP → 自动识别 → 预检与映射 → 确认导入 → 批次结果。GZCTF包和CTFd完整备份都在目标数据库做新增导入，不对源平台执行写入。

替代方案A：离线转换脚本转内部格式；维护成本较低，但用户需多步操作且不适合账号冲突处理。替代方案B：在线管理员API同步；可以增量拉取部分字段，但密码/插件字段与备份一致性存在限制，凭据管理和网络依赖较重。首版推荐原生ZIP适配，未来再增加API来源。

用户已选择：比赛题目转训练内容、账号与历史成绩保留。本版不复刻原比赛运行模式；原赛得分/队伍/提交结果进入独立历史档案，和训练排行榜分开。

## 3. 内容映射与预检

默认比赛/站点 → 技能树，原题型类别 → 类别，每个类别下建立同名默认技能，题目 → 题目库并关联技能。也允许选择已有目标路线/类别/技能，使用新增引用而不是重复题目。导入默认形成草稿，预检显示可直接发布/需补配置/不支持三类状态，不启动容器、不拉取镜像。

保留标题、Markdown正文、分类、难度、提示、静态Flag、动态模板、附件、启用状态、容器镜像/端口/资源/网络配置。容器题可同时带附件，不能丢附件或错误改变题型。重写本地附件/正文资源引用到实际存储位置，核对哈希、大小与缺失文件。外链仅保留并标记依赖，不在导入时自动请求任意外链。

不直接把旧截止日期、动态计分、血量奖励变成训练限制；保留来源元数据并列出不等价项。未知题型/插件、不可识别正则Flag、缺镜像配置必须逐项提示，不能生成貌似正确但无法通关的题。GZCTF的4道缺模板动态容器题按原GenerateDynamicFlag逻辑在实例创建时生成随机flag{GUID}，模板题按原模板语义转换，不当作配置错误；原赛TEAM_HASH以目标用户身份和稳定来源标识生成散列，不能使用固定TestTeamHash。未识别模板在预检中列出。镜像引用不等于镜像内容，Harbor凭据继续使用目标平台配置，不从包里覆盖。

## 4. 账号与历史数据

账号：用户名、邮箱、注册时间、封禁/验证状态迁为本地账号；标准公开资料保留在受保护的来源快照。自定义字段暂不猜测映射，不认识的非空表在预检中明确提示，等待真实备份核对。ID按“来源实例+源ID”建立映射；同名账号不能自动合并，邮箱冲突需显式处理，现有账号密码/权限不得覆盖。可逐项勾选SkipUserIds明确跳过账号创建并重新预检，历史保留但不自动绑定现有账号；跳过选择计入计划指纹，未知编号和重复源编号仍阻断。超长用户名提供明确重命名映射。导入源管理员默认作为普通用户，源会话、API令牌、重置令牌不迁移。

CTFd官方当前密码使用passlib bcrypt_sha256，目标使用ASP.NET Identity，无法原样复制后就能登录。用户已选择实现有格式/参数限制的旧哈希校验，首次成功登录转成本地哈希（Identity SuccessRehashNeeded）。不能将摘要视为明文、不能生成公用默认密码。兼容器只处理迁入账号明确标记的受支持CTFd摘要，原生账号继续使用本地Identity校验；不支持的哈希保留账号并列出需重置，绝不绕过校验。密码重置/修改之后旧摘要失效，已有账号冲突不覆盖其凭据。旧算法参数先验校验与上限控制，防止恶意工作因子耗尽资源。

历史数据：保存原比赛、队伍、队员关系、提交结果/时间、得分、奖励及解题记录的来源快照，提供管理端历史批次详情和账号个人历史页面。只展示用户自己的提交详情；管理员可查看全量，公共页面不泄露邮箱、提交Flag或密码摘要。默认不写入ChallengeProgress，避免原赛积分、未知是否看过WP的旧解题记录影响训练榜。队伍解题不自动分配给每个队员；保留队伍归属。成绩按原始记录保存，不用训练平台当前分值重算旧分。

## 5. 稳定性与权限

管理员上传/预检/导入；ZIP路径、重复条目、文件数、压缩/展开大小、真实解压字节均设上限。只解析数据，不执行SQL、插件、脚本或包内指令。原始账号资料与Flag不进入普通日志或公开预检响应。

预检返回批次标识与包指纹，执行绑定同一包、选项及目标版本；清晰区分错误/警告。来源实例标识必须显式选择，不能用本地题号作为全局键。相同来源相同包重复执行幂等，来源包变更不静默覆盖人工修改。数据库写入保持事务；文件先暂存、失败补偿，不能返回成功却遗漏关联内容。用户合并、角色提升、覆盖现有记录需明确选择，首版默认新增且保留原数据。

1. 安全包读取/格式识别、GZCTF解析器与真实样本结构回归（不提交用户原包或真实Flag进Git）。
2. 当前四层模型写入、资源存储、预检及幂等，再补管理员向导。
3. CTFd标准导出解析器、插件字段清单及测试夹具。
4. 账号映射/冲突/密码策略、历史记录保存；以真实CTFd完整备份作脱敏结构核验。
5. 集成测试：26题/19文件逐项核对、附带文件容器题、缺模板警告、停用状态、失败回滚、重复导入、两个来源相同ID不冲突、账号邮箱冲突、禁止权限提升、匿名不可读资料、历史积分不混入训练榜。
6. 浏览器测试：预检错误定位、目标选择、执行及批次结果；旧内部格式继续兼容。不得以合成备份通过代替真实CTFd备份验收。

## 8. 执行门槛及范围锁定

本轮实现两种ZIP适配、当前四层体系写入、账号迁入与旧密码兼容、历史档案、后台预检/批次页，新增离线与HTTP/浏览器测试。无需在源CTFd站上部署插件或开放数据库，也不更改比赛平台。现有内部ZIP格式继续支持。

CTFd真实完整备份缺失不阻塞公共标准格式实现及合成样本测试，但该校园站的插件、实际哈希格式及真实数据兼容性不得宣称验收完成。拿到真实包之后补充结构核对、样本回归和预检报告；不将用户账号、Flag或完整备份提交Git。

真实GZCTF包已通过本地完整HTTP预检/执行/重复执行验收，26题、7类别/技能、19资源全部保留；4道容器题补充附件可下载，不创建运行实例。与源比赛计分、分区、截止时间不等价的字段仅保留来源元数据，不伪装为现有训练功能。
