# 管理后台操作、Flag 提交与系统状态日志设计

日期：2026-10-05

## 目标与现状

管理员继续使用现有 `Role.Admin`：用户自行注册后，现有管理员在“用户管理 → 编辑用户 → 角色”选择 `Admin` 即可授权多个账号。所有 `Admin` 账号权限相同；本需求不新增角色、授权入口或权限层级。

现有 `/admin/logs` 展示 Serilog 系统日志，接口已有每页 50 条的偏移分页和级别筛选，但页面把整条消息直接铺在表格中，并将实时消息插入当前列表。现有日志不能可靠回答“谁对哪个目标执行了什么修改，结果如何”。现有 `ChallengeSubmissions` 保存用户、题目、时间、判定结果及提交值哈希，不能还原历史 Flag 明文；次数限制、不可访问等在判题前拒绝的请求没有对应提交行。

本功能从上线后记录结构化操作和 Flag 提交事件；历史 Serilog 日志仍可在“系统状态”查看，不伪造历史操作分类或 Flag 原文。

## 方案选择

采用独立的结构化操作记录和 Flag 提交记录，并保留现有系统日志。仅扩充通用 Serilog 记录会把业务审计与诊断消息混在一起，难以稳定提取目标名称和结果；仅按 HTTP 路径归类无法准确描述业务动作。共享写入服务负责字段约束，具体修改入口提供动作和目标信息，覆盖测试防止遗漏。

## 记录范围

### 管理员操作

记录所有会改变持久状态或产生外部副作用的管理员操作，不以 HTTP 动词作为唯一判断。范围包括现有及本功能上线时仍可用的用户与权限、题目、课节、技能树与类别、公告和资源、系统与 QQ 设置、令牌、导入、写作审核、班级与看板、管理员容器操作等入口。读取和搜索请求不产生操作记录；即使某个读取形式的接口实际创建草稿，也按状态变更记录。批量动作以批次为目标并记录受影响数量，能稳定取得单个目标时同时保留其名称和 ID。

额外记录用户主动创建和销毁靶场容器的操作。自动过期清理继续属于系统状态日志，避免误标为用户主动销毁。

每次尝试保存一条结构化事件：唯一 ID、UTC 时间、操作者 ID 与当时显示名称、操作者类型（管理员账号、管理令牌或普通用户）、动作代码、类别、目标类型、目标 ID 与当时名称、结果、必要的错误代码或简短原因，以及关联请求 ID。管理员修改成功与失败都记录；受保护修改请求被拒绝时，若能识别已登录操作者，也记录失败事件。匿名探测保留在系统状态日志中。批量事件的目标可以是批次 ID，详情显示受影响数量。

操作记录不保存请求正文、字段前后值、密码、Flag、令牌、密钥或异常堆栈。错误原因由服务端使用受控代码和经过清理的说明生成，避免把用户输入或秘密拼入记录。授权、校验、目标不存在、业务冲突及服务器错误均显示相应结果；记录自身写入失败时写系统错误日志，不能把缺失记录显示为成功。

### Flag 提交

为所有已登录用户发起的靶场 Flag 提交尝试保存独立事件，包括正确、错误、空值、次数限制、题目不可访问及其他被拒绝结果。每条保存事件 ID、UTC 时间、用户 ID 和当时名称、题目 ID 和可取得的当时名称、结果、必要的拒绝代码、关联提交 ID（若判题产生了 `ChallengeSubmission` 行）及用户实际提交的原文。绝不把服务端预期 Flag、请求正文或原文写入通用系统日志或操作日志。

Flag 原文在活动数据库中以应用数据保护机制加密保存，仅通过 `Admin` 授权的详情接口解密返回。新增记录从上线时开始；旧 `ChallengeSubmissions` 的哈希不能还原为原文。原文在提交满 30 个 24 小时后不可通过接口读取，每日清理任务将加密字段从活动数据库清除；事件的用户、题目、时间、结果和原因继续保留。清理使用 UTC 时间并支持重复运行。活动数据库的清理与应用备份的保留策略是不同的：备份按部署方已有策略管理。

### 系统状态

现有 Serilog 数据源、级别和实时消息机制继续提供系统状态。系统状态详情可展开完整消息，并在存在时显示来源和异常信息；不把新的 Flag 原文写入 Serilog。系统状态的现有存储和保留规则不因本功能改变。

## 后台交互

`/admin/logs` 改为三个标签页，依次为“操作日志 / Flag 提交 / 系统状态”，默认显示操作日志。仅 `Admin` 可以访问页面及其数据接口；通过客户端隐藏入口之外，服务端独立检查权限。三个标签页都按 UTC 时间及唯一 ID 倒序、服务端分页，默认每页 20 条，返回总数并提供页码切换。筛选或搜索变化时回到第一页；分页结果在同一排序下稳定。

各页先显示紧凑摘要，逐条点击展开详情；切页或切换筛选后收起已展开项。操作日志摘要含时间、操作者、类别、动作、目标和结果；按类别、结果筛选，并可按操作者或目标名称及 ID 搜索。Flag 提交摘要含时间、用户、题目和结果；按结果筛选，并可按用户或题目名称及 ID 搜索。Flag 原文只在展开详情时获取和显示；超过 30 天或历史记录显示“原文已清除 / 不可用”。系统状态按级别筛选，摘要显示时间、级别、来源和截短消息，展开后看全文。

系统状态的实时消息到达时，页面只提示“有新记录”；管理员点击提示后回到第一页并刷新。查看旧页或展开详情时不自动插入新行，避免顺序和页码跳动。操作与 Flag 事件可以使用同样的刷新提示，但无需增加实时推送依赖。

日志分类采用稳定的服务端动作与类别代码，前端将其翻译为可读名称；现有中、英文界面提供相应文本。类别按业务域划分，至少覆盖用户与权限、题目与课节、技能树与类别、容器、系统设置、内容与导入、班级与看板；新增管理员写入口必须选择类别和动作代码。

## 组件与数据流

1. 管理员或用户发起写请求。操作入口提供动作、目标和操作者上下文；统一记录服务在业务结果明确后写入成功或失败事件。对进入控制器前被拒绝的已认证请求，由请求边界记录可得的错误上下文。批量和删除动作在目标消失前取名称，令牌操作以令牌标识而非令牌值作为目标。
2. Flag 提交入口在权限、输入和次数检查前建立尝试上下文，判题后写入结果；因此有正常提交 ID 时关联现有提交记录，提前拒绝时也有独立事件。记录写入与现有判题逻辑分开，避免更改得分和提交次数语义。
3. 管理员查询接口分别读取结构化操作事件、Flag 事件和现有 Serilog 日志，统一提供筛选、总数和分页。详情接口按需读取单条；Flag 原文再次检查 30 天期限与权限。
4. 每日任务清除到期原文；清理失败写系统状态并在下次运行重试。系统日志写入继续使用现有 Serilog sink。

数据库为新事件建立时间与 ID 排序索引，以及常用类别、结果、操作者或题目筛选所需索引。操作记录与 Flag 提交记录各有独立表，避免把 Flag 原文存入通用日志表。迁移为增量迁移，不改变既有账号、角色、提交哈希或系统日志。

## 错误处理与边界

- 日志查询失败显示错误与重试入口，不把失败当作空列表。
- 管理员权限在每次请求时按现有规则核验；被降权的账号不能继续取日志或 Flag 详情。
- 展开 Flag 详情时再次检查访问权和期限，避免列表加载后的权限或到期变化暴露原文。
- 提交值不出现在应用请求日志、操作错误原因、浏览器控制台或通知中。
- 审计写入失败必须进入系统错误日志，便于发现覆盖缺口。外部容器副作用无法与数据库审计记录组成单一事务，测试分别验证副作用结果和日志结果；不因日志失败重复执行容器动作。

## 验收与验证

- 已注册用户经现有角色编辑入口获 `Admin` 后可进入后台；多个 `Admin` 账号权限相同。普通用户和降权用户不能读取三个标签的数据。
- 管理员写入口清单与审计动作清单逐一对照；测试覆盖典型成功、校验失败、授权失败、业务冲突、删除与批量操作，验证目标名称和 ID、结果、错误原因，且没有敏感正文。
- 用户主动创建及销毁容器有成功或失败事件；自动过期清理不冒充用户操作。
- Flag 正确、错误和提前拒绝均出现；已判题事件关联现有提交 ID；原文只在授权展开时显示。满 30 天后接口不返回原文，每日任务清空字段，其他元数据仍可查。
- 三个标签各自分页，切换筛选重置页码，折叠详情正常，实时新消息不会改变正在看的页；系统状态仍可查看既有日志。
