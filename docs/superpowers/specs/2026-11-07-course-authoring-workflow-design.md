# 技能树课程创建与编排流程重规划

日期：2026-11-07

状态：已确认并在本地实现自上而下建课、整棵技能树草稿与统一发布；尚未部署正式环境。执行与验证记录见同日期执行计划和课程编排验证报告。

## 目标与已确认约束

管理员的主要任务是建好一门可以学习的课程。默认从技能树开始，边创建类别和技能，边加入课节与题目；不应要求先理解四个资源库、分别保存引用，再回来发布。

保留数据层级：技能树 → 类别 → 技能 → 题目 / 课节。资源可以跨父级复用，同一内容的账号完成记录与得分共用。复用不复制账号记录，不改变现有题目容器入口、Harbor 配置和比赛平台。

新界面沿用平台主题与用户选择的强调色，支持浅色、深色与跟随系统。正文、提示、禁用状态和焦点均使用现有主题变量。

## 当前路径及问题

| 任务 | 现有操作 | 问题 |
| --- | --- | --- |
| 新建技能树 | 列表弹窗填信息 → 树编辑 | 仅能选已存在类别，没有继续建课引导 |
| 加类别 | 跳类别库新建 → 关联技能树，或回树页选择 | 父级上下文丢失，多次保存 |
| 加技能 | 从类别页跳技能库 → 新建 → 回类别页选择并保存 | 新建不自动关联当前类别 |
| 加内容 | 离开技能页去课节库/题目库 → 创建编辑 → 发布时重选路径 | 路径重复选择，未保存的编排容易丢失 |
| 预览 | 请求服务器草稿 | 本地未保存的顺序与关联不会体现；本轮已补回归并修复 |
| 内容发布 | 选择的技能列表覆盖所有既有内容引用 | 用户容易将“新增到当前课程”误解为仅增加引用 |
| 保存与发布 | 树、类别、技能、内容各有入口 | 不易知道哪些改动已影响学员 |

重要事实：现有草稿版本主要覆盖树→类别关系。类别→技能、技能→内容是共享实时数据；树名/简介等字段也并非完整快照。因此不能仅调整按钮，就宣称“发布前学员完全看不到改动”。

## 三种方案与推荐

1. **课程编排工作区（推荐）**：以技能树为入口，左侧大纲、右侧编辑。支持自由切换、原地新建和库复用，适合首次创建与长期维护。
2. **分步向导**：依次填树信息、类别、技能、内容、发布检查。首次使用清楚，但维护已有课程与跨级修改不便。推荐只把它作为空白课程的引导，不强制每次走完整向导。
3. **保留当前页面，加上下文抽屉**：改动较小，能缩短跳转，但仍保留多套保存规则和分散入口。适合作为过渡，不作为最终主流程。

## 推荐工作区

```text
左侧课程目录                          右侧当前节点

    HTTP 与浏览器                     所属路径：Web 基础 / Web 入门
      课节：请求与响应                 被其他课程引用：2 处（查看）
      题目：观察请求头
    SQL 注入基础  ← 当前              内容编排
      课节：基本语法                    1. 课节：基本语法    编辑 / 移出
      题目：第一个注入                  2. 题目：第一个注入  编辑 / 移出
    + 添加技能                         + 新建课节  + 新建题目  从库添加

```

目录中显示内容类型、草稿/发布状态、停用状态和待保存标记。提供拖拽与键盘可用的上移/下移。窄屏目录改成可收起抽屉，编辑区占满可用空间。

基本信息、课程编排与发布检查属于同一个工作区；内容编辑沿用已有完整 Markdown 编辑器和题目设置表单，不把复杂表单塞进多层弹窗。题目表单保留 CPU、内存、存储、网络模式、Flag 模式、提交限制和分值配置，不在重排流程时丢失高级功能。

## 日常建课流程

1. 点击“新建技能树”，默认只必填名称。创建草稿后直接进入工作区；简介、封面和图标允许稍后补。
2. 在树下点击“添加类别”：默认“新建类别”，次选“从库添加”。新建成功后自动关联当前树并选中。
3. 在类别下点击“添加技能”：新建后自动关联当前类别；无需返回技能库操作。
4. 在技能下选择“新建课节”“新建题目”或“从库添加”。新内容自动带入当前树、类别、技能上下文。
5. 进入完整内容编辑器；保存后“返回课程编排”回到原目录节点、原滚动位置。不得要求重新选择发布路径。
6. 顶部始终显示保存状态。预览前保存当前改动；保存失败停留原地并保留输入。
7. 点击“检查并发布”，展示学员实际可见内容、阻塞错误、提醒和影响范围；确认后发布并给出学员入口。

空白课程只显示与当前阶段相关的下一步，如“先添加一个类别”；有内容后改成自由编排，不强制线性向导。

## 复用与编辑共享资源

- “新建”与“从库添加”分开命名；后者展示名称、类型、发布/停用状态、内容数量、既有引用位置与搜索筛选。
- 默认添加操作只增加当前父级引用，保留该内容在其他课程的全部关联。管理所有引用是独立操作，需要明确影响范围。
- “从当前目录移除”只解除引用，不删除资源与完成记录。真正删除放在资源库高级操作中，保留影响确认。
- 编辑共享资源前展示受影响课程。目前只有树→类别关系属于单棵树的编排；类别→技能及技能→内容的顺序与关联仍随共享父级影响所有引用。若新工作区要支持“只调整本课程”，必须新增按引用覆盖或版本快照，不能把现有共享写入换个按钮名称就当成本地操作。
- “复制为独立内容”不能悄悄替代引用；复制会产生新的内容身份，默认不继承旧内容得分与完成记录，须明确说明。
- 独立资源库继续保留，用于批量维护、导入、搜索和跨课程复用；不再是默认建课必须经过的路径。

## 保存、发布与冲突

### 共同要求

- 顶部固定显示“有未保存修改 / 保存中 / 已保存 / 保存失败”。按钮名保持一致。
- 切节点先保存当前内容或让用户明确保留/放弃，不静默丢弃。刷新/关闭页面有未保存内容时提醒；课节原有本地草稿恢复继续保留。
- 保存失败可重试，父级创建成功但关联失败时保留已创建 ID，重试关联，不再次创建重名资源。
- 并发版本冲突停止写入，保留本地输入，展示重新加载与差异核对；不自动带新版本号覆盖别人的变更。
- 自动保存可以用于草稿，但不得自动发布。显示保存完成不等于已向学员发布。
- 预览必须读取当前完整已保存草稿，明确标注管理员预览；不能混入其他课程或私有题目答案。

### 已确认：整棵技能树草稿与统一发布

用户已确认发布前全部隐藏，因此需要对课程的可见元数据、目录、节点与内容版本建立完整草稿/发布边界。发布时校验全图依赖并原子切换活动课程版本；其他课程继续引用自己的已发布版本，不被某个共享技能的草稿修改顺带更新。

实现前需明确内容版本的深度：课节正文、附件引用与题目说明均需固定到发布版本；题目 Flag、容器镜像、计分与运行中实例属于额外运行契约，不能只靠前端或目录快照隔离。应在实施计划中单列这些服务的版本解析与旧实例兼容检查，并保留稳定内容 ID 维持去重得分和完成记录。若本阶段只完成目录隔离，必须明确写成“目录发布”，不能宣传整门课程隔离。

### 未选方案：保留当前共享生效规则

只整合入口并继续即时生效虽然成本较低，但不符合本轮用户确认。正式交付不能用这条捷径替代统一发布；此前两个定点修复仅用于改善现版本。

## 统一发布的实现边界

以下行为契约已纳入实现与回归验证，具体文件及迁移见执行计划：

1. **草稿工作区**：一棵树有独立工作区版本及并发令牌。树信息、封面引用、类别/技能的元信息、排序、内容放置位置均写草稿。草稿文件不可通过猜测静态 URL 绕过权限读取。
2. **已发布快照**：学员读取活动课程快照，按稳定资源 ID + 不可变版本引用解析节点和课节正文/题目说明/附件。发布原子切换活动版本；保存失败或发布失败不影响旧版。不能仅复制目录、仍按实时技能名或课节正文渲染。
3. **复用与版本**：从库添加选择已有资源的可用版本，保留身份与完成记录；编辑产生待发布版本，不原地覆盖被其他课程引用的不可变版本。其他已发布课程继续固定旧版本；升级到新版本需显式纳入发布检查。
4. **运行与计分约束**：同一稳定题目 ID 的 Flag、镜像、运行参数和计分规则不能在不同课程中默默出现互相冲突的有效版本。第一次实现应阻塞不兼容的共享题目发布，要求把受影响课程一起纳入经过确认的发布批次，或明确复制为独立题目。不能自动复制、重复发分或静默改动其他课程。正式实施前为相同题目在两门课发布不同运行版本补集成测试。
5. **运行中实例**：实例记录其启动所用版本；发布新配置不强杀旧实例。提交 Flag、延长和停止仍解析原实例契约；无实例的静态题按活动题目版本验证。保留一题一份有效计分身份，并沿用现有审核、补分、撤销与审计规则。
6. **原子提交与失败恢复**：先完成依赖校验与文件可读性验证，再在同一数据库事务中切换受影响活动指针。通过 outbox/可重试任务通知缓存失效；缓存更新失败不能造成未提交版本可见。附件先写入安全存储，数据库事务失败后回收无引用上传，不能回滚删除旧版正在使用的文件。
7. **旧数据迁移**：把现有发布状态固化为初始快照，保持资源 ID、引用顺序、账号、成绩、附件路径和运行中实例兼容；对含未发布/停用内容的混合目录只固定当前实际可见部分。迁移前后对同一学员的公开目录与计分结果作对比，未经过显式管理员操作不得变化。
8. **资源库与返回路径**：课程内编辑带工作区和父节点上下文。资源库可独立建草稿与管理版本；从库编辑返回课程时不会丢失原大纲位置。旧后台入口仍可到达资源管理，但不能再绕过统一发布直接修改活动课程。

## 发布检查

检查按重要程度显示，逐项可点回对应节点：

- 阻塞：结构引用失效、版本冲突、权限不足、题目必填配置缺失、资源写入未完成。
- 阻塞还包括内容必需或已引用的本地附件缺失/不可读取，沿用现有发布校验；不应把这类故障降为提醒。
- 提醒：空类别/空技能、停用技能、未发布内容、封面/简介缺失、尚未配置的可选附件。
- 对容器题：展示镜像、服务端口及配置检查结果；“格式正确”与“已在题目机实际启动验证”分开，不把未知镜像当已可用。
- 结果：学员可学习的课节/题目数量、将新增/移除的目录项、共享资源影响范围。统计按内容身份去重。
- 新内容第一次发布、已有内容重新编排、解除引用分别明确描述。不以“发布”暗中重置其他课程的引用。
- 发布成功后保留可追溯版本信息。若要回滚，应整体恢复匹配版本；不把旧应用镜像直接切回已升级数据库。

## 计分与既有数据影响

保留稳定题目 ID 与通关记录，不等于冻结排行榜分数。当前原生题目的累计分投影会受到题目现行分值、启用状态和是否仍存在可见发布引用的影响；移除最后一个可见引用、停用或改分都可能改变当前榜单。迁入题目的冻结分值与原始成绩基线有独立规则，不得通过编排重建题目来绕过。

新工作区的发布检查必须显示计分相关影响，并沿用现有计分服务与管理员审计/并发控制，不在前端另算一套总分。若业务希望目录整理绝不影响已获得积分，需要先单独确认并设计计分规则，不能把它当作本次界面调整的隐含结果。

## 验收场景

- 从空白技能树连续新建类别、技能、课节和题目，全程不被迫去资源库且不重复选父级。
- 从库添加已有内容，原课程引用和历史通关得分不变；取消当前引用不删除内容。
- 共享技能影响范围真实可见；对另一门课程的影响符合选定发布策略。
- 保存冲突、断网、父级已创建但关联失败均可恢复，不重复创建、不丢草稿。
- 更改顺序后预览与发布一致；发布检查准确识别学员不可见内容。
- 题目编辑、课节 Markdown、附件、动态容器、Flag、排行榜和迁入账号继续正常。
- 桌面和手机、浅色和深色、个人强调色、键盘操作和减少动画偏好均验证。

## 本轮边界

用户确认后已完成本地编排工作区与发布快照实施，并经过规范/质量审查、迁移及回归验证。后续发布包和正式部署属于独立操作；本地完成不代表已上线。实现差异、操作方法和测试范围见 `2026-11-07-course-authoring-workspace.md`、`2026-11-07-course-authoring-operations.zh-CN.md` 及 `docs/qa/2026-11-07-course-authoring-verification.md`。
