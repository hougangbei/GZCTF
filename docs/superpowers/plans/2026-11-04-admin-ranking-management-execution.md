# Admin Ranking Management Implementation Plan

> **For agentic workers:** Use subagent-driven-development to implement and independently review. No Astra.

**Goal:** 实现已批准的排行榜管理1–7、等级门槛和学员榜个人资料展示。

**Architecture:** 管理修改通过带幂等编号和乐观版本的调整账本提交；旧基线不可变，通关纠错由关联状态记录补偿与恢复。统一成绩服务同时供管理榜、公开榜、等级和图表使用，隐藏覆盖与封禁独立。

**Tech Stack:** .NET 10 / EF Core PostgreSQL / Mantine React / ECharts / Playwright.

### Task 1: 管理服务、纠错状态和接口

- [x] 新增管理账本、用户可见性覆盖、等级配置和必要纠错模型/迁移；定义稳定DTO与API并先回报前端。
- [x] 先写合成集成测试：加100减50、目标总分、撤销一次、重复操作编号、版本冲突、权限和失败回滚。
- [x] 实现 `/api/admin/learning-rankings` 分页搜索与包含隐藏/封禁的列表、`/{userId}` 明细、`/{userId}/adjustments`、`/adjustments/{id}/reverse`、`/{userId}/visibility`、`/{userId}/challenges/{challengeId}/solve`（补记）、同路径 DELETE（撤销），`/operations` 日志、`/export` CSV。
- [x] 管理员原因必填、正负和目标值有界，用户版本/操作编号防重复。隐藏不改Role；封禁不公开；CSV 仅安全公开身份/成绩，防公式注入。
- [x] 通关撤销同步进度和分数，旧题恢复冻结分值，原生题按当前计分；重新正常提交Flag走同一恢复路径，题目合并保留状态，绝不重新获得两份分数。进度、账本、每日投影同事务，失败回滚。

### Task 2: 等级、统一查询和排行榜接入

- [x] 增加 `/api/admin/learning-rankings/levels` GET/PUT，以及 PUT 的预览接口：严格递增0起点门槛、连续等级、版本冲突、影响人数预览。默认0/1000/3000/6000/10000/15000/22000/30000/40000/50000，负分Lv.1。
- [x] 公共榜返回用户等级、Bio；成绩包含旧分+有效原生+调整。图表按调整时间起落，移除通关/重新完成与解题数对齐；调整不会改写原历史。
- [x] 所有读取和写入共享一致计分；缓存失效，失败不半更新。数据库升级保留旧数据。

### Task 3: 管理界面与前台

- [x] 新建 `hooks/useRankingAdmin.ts` 独立类型，后台 `pages/admin/rankings/Index.tsx`：学员成绩、调整记录、等级设置；学员详情抽屉展示当前分数和调整/通关操作。
- [x] 功能表单显示当前/目标和差额，原因必填，确认后提交唯一operationId及version，成功刷新；冲突提供刷新。日志可看前后值和原因，撤销需原因。等级编辑先预览再确认，CSV通过鉴权下载。
- [x] 导航加入排行榜管理；前台表格排名、用户名、等级、个性签名、解题数、积分，手机折叠资料行。个人简介纯文本、空值/长值安全。沿用平台主题。
- [x] 先浏览器回归再实现：权限、搜索/分页、改分/冲销、补记撤销、可见性、等级预览及手机布局。

- 前端单元35项通过；类型检查及生产构建通过。完整浏览器回归47项通过，后续新增不可核实冻结分值界面测试通过，总计48项不同检查；其中最终10项后台检查全部通过。
- 独立前端规格/质量审查发现并修复：全局SWR保留上人详情导致误操作风险；历史分页不足无法撤销旧调整；全局日志缺少被调整人；长签名手机不可展开；新增个人历史也须禁用旧用户缓存。各有延迟响应、分页旧记录、明细目标和手机签名回归。
- 独立后端审查发现并修复：新增DetailsJson需与EF迁移一致；新训练题纠错明细不可沿用旧冻结值。另通过并发红绿回归证明题目合并等待锁时Serializable旧快照可能遗漏刚提交的通关，已在共用记分锁下改ReadCommitted，合并保护重新核对。
- 合并互相冲突的同一学员纠错归属时明确拒绝，不猜测归属；无冲突纠错和冻结分值可以迁移到保留题。无法核对旧题冻结值时不允许撤销，不能退回当前题目分值猜扣。
- 所有管理写操作均登记审计，等级预览有只读审计记录。手工总分在允许范围内校验，既有64位累计分数账号不因隐藏等无关操作被错误拒绝。排行榜/详情统一投影，来源基线不改写。
