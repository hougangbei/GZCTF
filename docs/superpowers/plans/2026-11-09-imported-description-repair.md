# 导入题目补正文后仍被阻止发布

根因链路：CTFd导入为zh/en各生成一份标题正文；当前题目编辑器只更新en，merge保留其他语言；导入原正文为空时，只补en后zh仍为空，课程发布检查以Any空Body阻止。用户从课程定位进入，非全局题目库与冻结课程错位。

修复范围：维持全部既有语言正文完整的发布要求。检查返回具体缺失语言。题目编辑器提示其他空白语言，提供显式“保存并补齐空白语言”；仅复制当前有效标题/正文到原有语言空字段，不新增语言、不覆盖已有非空正文/翻译，不改Flag/镜像/积分/题目身份。普通保存仍只更新当前en。与课程修复清单、版本冲突保护集成，不新增数据库迁移。

- [x] 新增前端失败用例：zh空/en补全、显式补齐、已有翻译不覆盖、普通保存不改其他语言。
- [x] 新增集成失败用例：真实双语言题只保存en仍被拦截，检查能指出zh；补齐后检查与发布成功，库中原题不被覆盖。
- [x] 实现最小helper、显式按钮、结构化缺失语言诊断和中文提示。
- [x] 浏览器复现两语言导入场景，保存补齐后统一复查；测试非空翻译保留、冲突/失败不误报。
- [x] 后端单元/集成顺序执行，前端单元/类型/构建/相关浏览器回归；独立审查。暂不自动部署。

## 验证结果

先验证前端显式补齐断言失败、集成检查缺失语言断言失败，再修复并通过。376后端单元、317集成（无跳过）、90前端单元、类型/生产构建通过。35项相关浏览器用例通过，包括真实双语言表现的模拟接口回归：普通保存仍明确报告zh空正文，显式补齐后复查通过，已有ja正文保留。集成测试使用真实服务/数据库验证只补en仍被拦截、补齐后发布成功且原题目库内容与积分未被覆盖。独立代码审查通过。未构建发行包或部署正式平台。
